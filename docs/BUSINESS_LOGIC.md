# 业务逻辑与数据影响

本文档集中说明当前代码实际实现的业务流程、状态、金额计算和数据副作用。内容以 `internal/infrastructure/persistence/gorm/business_repository.go`、领域模型和测试为准；页面文案或可选状态不一定代表已经实现对应的库存、财务联动。

## 1. 核心原则

- 所有业务数据都带 `tenant_id`，接口从 JWT 中取得当前租户和操作人。
- 库存数量不能直接新建、编辑或删除，只能由采购、销售、维修领料及删除反处理改变。
- 应收、应付和资金流水不能通过通用 CRUD 直接新建或编辑，必须由业务单据或收付款动作产生。
- 销售、采购和维修单删除必须填写原因，并额外要求 `document_delete` 权限。
- 金额字段使用十进制定点数保存；仓储层运算目前会转成 `float64` 后写回。
- 创建销售、采购、维修时，主单和创建阶段的副作用处于同一个数据库事务中，任何一步失败都会回滚本次创建。

## 2. 流程与数据影响总览

| 业务动作 | 库存影响 | 往来账影响 | 资金账户影响 | 审计/关联数据 |
| --- | --- | --- | --- | --- |
| 创建采购单 | 入库，新增采购批次 | 新增应付 | 无 | 采购明细、库存流水 |
| 创建销售单 | 按选定采购批次出库 | 新增应收 | 无 | 销售明细、成本分摊、库存流水 |
| 应收收款 | 无 | 冲减应收 | 增加账户余额 | 新增收款流水，同步销售单 |
| 应付付款 | 无 | 冲减应付 | 减少账户余额 | 新增付款流水，同步采购单 |
| 完成维修单 | 配件批次出库 | 新增客户应收；外协生成供应商应付 | 无 | 维修明细、库存流水 |
| 创建工程项目 | 无 | 当前不生成应收 | 若有结算/已收金额，直接增加账户余额 | 新增工程收款流水 |
| 对账单结算 | 无 | 按明细逐笔冲减应收 | 增加账户余额 | 更新对账单及明细，新增收款流水 |
| 删除销售单 | 恢复原采购批次和总库存 | 应收冲销 | 已收款生成反向付款 | 删除快照、处理明细、操作日志 |
| 删除采购单 | 采购库存冲减并删除批次 | 应付冲销 | 已付款生成反向收款 | 删除快照、处理明细、操作日志 |
| 删除维修单 | 当前不恢复已领配件 | 应收、外协应付冲销 | 已收/已付生成反向流水 | 删除快照和处理记录 |

## 3. 采购流程

### 3.1 创建采购单

创建采购单时立即执行入库和应付确认，不等待状态变成“已入库”或“已完成”。如果未传状态，后端默认写入 `已完成`。

处理顺序：

1. 根据商品 ID、编码或名称查找商品；找不到时可自动创建基础商品资料。
2. 计算 `total_amount = quantity * price`。
3. 创建 `purchase_orders` 主单和 `purchase_order_items` 明细。
4. 创建 `inventory_batches` 采购批次：入库数量和剩余数量均等于采购数量。
5. 更新 `inventory_stocks` 汇总库存并写入 `inventory_movements` 入库流水。
6. 新增一笔 `payables` 应付账款，初始已付为 0，余额为采购总额。
7. 汇总更新供应商的 `payable_balance`。

采购入库后的移动平均成本：

```text
新平均成本 = (原库存数量 * 原平均成本 + 入库数量 * 采购单价) / 新库存数量
库存金额 = 新库存数量 * 新平均成本
```

采购批次状态：

| 条件 | 状态 |
| --- | --- |
| 剩余数量等于入库数量 | `未销售` |
| 剩余数量大于 0 且小于入库数量 | `销售中` |
| 剩余数量小于等于 0 | `已销售完成` |

### 3.2 采购付款

付款动作只处理未结清应付，可指定单笔应付，也可按供应商从最早到期记录开始依次核销。

- `paid_amount += 本次分配金额`
- `balance_amount -= 本次分配金额`
- 余额为 0 时状态为 `paid`；部分付款为 `partial`；未付款为 `unpaid`
- 同步采购单的 `paid_amount` 和 `payable_amount`
- 新增付款资金流水，所选资金账户余额减少
- 刷新供应商 `payable_balance`
- 付款超过可核销余额时，超出部分不会入账，并通过 `remainingAmount` 返回

应付默认到期日为采购日期后 30 天。

## 4. 销售流程

### 4.1 创建销售单

创建销售单时立即出库并生成应收，不等待“已发货”等状态。销售必须选择一个或多个可用采购批次，系统不会自动替用户选择来源。

批次校验规则：

- 批次必须存在、未删除且剩余数量大于 0
- 批次商品必须与销售商品一致
- 批次仓库必须与销售仓库一致
- 所选批次剩余数量合计必须覆盖销售数量
- 多批次按前端提交顺序依次扣减

处理顺序：

1. 预校验所选采购批次并计算真实销售成本。
2. 计算销售金额、成本和毛利。
3. 创建销售主单。
4. 扣减采购批次剩余数量。
5. 按批次创建销售明细和 `sales_cost_allocations` 成本分摊。
6. 扣减 `inventory_stocks`，写入销售出库流水。
7. 检查客户信用额度。
8. 创建全额未收的应收账款，并更新客户欠款汇总。

金额公式：

```text
销售总额 = 数量 * 销售价
销售成本 = 各采购批次分配数量 * 对应采购单价之和
平均成本价 = 销售成本 / 销售数量
销售利润 = 销售总额 - 销售成本
毛利率 = 销售利润 / 销售总额 * 100%
```

客户存在正数信用额度时，系统校验：

```text
当前未结应收 + 本次销售总额 <= 客户信用额度
```

超额时整个销售创建事务回滚，库存批次、库存汇总和主单都不会保留。

### 4.2 应收与收款

销售创建后应收初始值为：

```text
total_amount = 销售总额
received_amount = 0
balance_amount = 销售总额
```

到期日优先使用客户 `credit_days`；未设置时根据结算周期推导：月结 30 天、季结 90 天、半年结 180 天、项目验收结算 30 天。设置了 1 至 28 的 `payment_day` 时，会调整到对应月份的指定日。

应收状态：

| 条件 | 状态 |
| --- | --- |
| 余额小于等于 0 | `paid` |
| 已收大于 0 且仍有余额 | `partial` |
| 未收且超过到期日 | `overdue` |
| 未收且未到期 | `unpaid` |

收款可指定一笔应收，也可按客户从最早到期记录开始依次核销。成功核销后：

- 更新应收已收金额、余额和状态
- 来源为销售时，同步销售单 `received_amount`、`receivable_amount`
- 新增收款资金流水，所选账户余额增加
- 更新客户 `receivable_balance`
- 超过可核销应收的部分不入账，通过 `remainingAmount` 返回

## 5. 维修流程

### 5.1 费用和利润

维修单可包含收费项、服务费、配件、外协和其他成本项。

```text
维修收入 = 服务金额 + 上门费 + 检测费 + 安装费 + 配件销售额 + 其他收费项
维修成本 = 配件实际批次成本 + 外协成本 + 人工成本 + 运输成本 + 其他成本
维修利润 = 维修收入 - 维修成本
```

维修配件必须选择具体采购批次。配件销售金额计入收入，批次采购成本计入成本。

### 5.2 完成维修

只有维修状态为 `completed`、`已完成`、`结算完成` 或 `维修完成` 时才触发完成处理。当前页面只提供 `已完成`。

完成处理包含：

1. 对每个配件明细校验采购批次并扣减批次数量。
2. 扣减库存汇总，写入 `repair` 类型的领料流水。
3. 按实际批次成本回写配件成本，重新计算维修成本和利润。
4. 维修收入大于 0 时生成来源为 `repair` 的客户应收。
5. 外协费用按供应商汇总，分别生成来源为 `repair_outsource` 的应付。
6. 设置 `inventory_done` 和 `settlement_done`，避免重复领料和重复生成往来账。

外协明细有金额但没有供应商时，完成处理失败。

## 6. 工程流程

工程状态可选：`计划中`、`施工中`、`验收中`、`已验收`、`已结算`、`已暂停`、`已取消`。

当前实际联动较轻：

- 创建工程时，如果 `received_amount > 0`，按已收金额创建工程收款流水。
- 否则如果 `settle_amount > 0`，按结算金额创建工程收款流水。
- 收款会增加指定资金账户余额，未指定账户时使用现金。
- 当前工程创建不会生成应收账款，也不会自动领料或扣库存。
- 页面上的施工日志、材料、相机等动作目前没有完整的仓储副作用实现；不能仅凭动作返回成功判断数据已经落库。

因此，工程状态目前主要用于展示和筛选，并不是严格的状态机。

## 7. 客户对账单

### 7.1 候选业务

候选来源以应收账款为主，可包含销售和维修应收。默认只显示：

- 当前客户的记录
- 余额大于 0 的记录
- 尚未加入其他有效对账单的记录
- 符合日期、关键词和付款状态筛选的记录

### 7.2 生成对账单

必须选择客户和至少一笔应收或销售单。生成过程在事务中完成：

1. 校验所有业务属于同一客户。
2. 校验业务尚未加入其他对账单，防止重复对账。
3. 必要时为旧销售数据补建应收。
4. 汇总总额、已收、未收和客户累计欠款。
5. 创建对账单主表及逐笔明细。
6. 初始状态为 `unconfirmed`。

对账单状态：

| 状态 | 含义和数据影响 |
| --- | --- |
| `unconfirmed` | 已生成，尚未确认；不改变应收和资金 |
| `confirmed` | 重新同步各明细对应应收金额并确认汇总；不产生资金流水 |
| `settled` | 所有明细未收余额已结清；产生收款流水 |

明细结算状态使用 `unpaid`、`partial`、`paid`。

### 7.3 对账单结算

结算前会重新同步应收，随后按对账单明细日期和 ID 顺序逐笔核销。

- 未传金额或金额小于等于 0 时，默认尝试结清全部未收金额
- 指定金额不足时允许部分结算
- 更新应收和对应销售单的已收/未收金额
- 更新对账单明细的已收、未收及状态
- 按实际核销金额创建一笔“客户对账单收款”资金流水
- 刷新客户欠款和对账单汇总
- 仍有未收余额时，对账单最终保持 `confirmed`；全部结清才为 `settled`
- 已经 `settled` 的对账单重复结算不会再次入账

## 8. 资金账户与资金流水

- 收款流水使账户余额增加，付款流水使账户余额减少。
- 指定账户不存在时，系统会自动创建零期初余额账户。
- 新建资金账户时，当前余额初始化为期初余额。
- 后续编辑账户不能直接修改期初余额和当前余额。
- 业务收付款必须从应收、应付或对账单入口登记。
- 当前通用创建接口会拒绝新建 `finance`，因此页面展示的“日常收入/日常支出”尚不能实际保存。
- 仓储中保留了日常记账校验和账户余额调整函数，但目前没有接入可持久化的 API；`book` 动作会落入通用 accepted 响应，不代表已经写入资金流水。

## 9. 单据删除与反处理

销售、采购和维修删除均为数据库事务。系统先保存删除前快照，处理库存和财务，再软删除主单；任何一步失败时整笔删除回滚。

删除记录状态从 `PROCESSING` 变为 `SUCCESS`，并记录：删除人、原因、时间、原始快照、库存是否处理、财务是否处理以及处理明细。

### 9.1 删除销售单

限制：

- 删除原因不能为空
- 已删除订单不能重复删除
- 状态为 `已出库`、`已发货`、`outbound`、`shipped` 或 `delivered` 时拒绝删除
- 缺少成本分摊或库存批次信息时拒绝删除，防止错误恢复库存

反处理：

- 按原成本分摊把数量恢复到对应采购批次
- 增加库存汇总并写入 `ORDER_DELETE` 入库流水
- 将销售应收余额置零并标记 `已冲销`
- 对对账单中的相关明细置零并重新计算对账单
- 已产生收款时创建等额反向付款流水，减少原收款账户余额
- 销售单标记 `已删除`，已收和未收金额归零

### 9.2 删除采购单

只有对应采购批次完全未被销售或领用时才能删除。任一批次剩余数量小于入库数量，整笔删除会被拒绝。

反处理：

- 从库存汇总扣除原采购数量，写入 `PURCHASE_DELETE` 出库流水
- 将采购批次剩余数量置零并软删除
- 冲销对应应付并刷新供应商欠款
- 已产生付款时创建等额反向收款流水，恢复原付款账户余额
- 采购单标记 `已删除`

### 9.3 删除维修单

反处理会冲销维修应收和外协应付；已收款生成反向付款，已付款生成反向收款，并刷新客户与供应商往来余额。

当前实现不会恢复已经由维修完成处理消耗的配件批次和库存汇总，删除记录中的 `stock_processed` 也会保持 false。已完成且领料的维修单删除前应人工评估库存影响。

### 9.4 状态动作的边界

销售的 `approve`、`void`、`return` 动作目前只修改状态为 `已审核`、`已作废`、`已退货`，不会自动恢复库存、冲销应收或生成退货流水。采购的“退货/取消”等页面状态同样没有完整反处理逻辑。

需要发生库存或财务反向变化时，应使用已经实现的删除反处理流程，或先补充专门的退货/作废业务逻辑。

### 9.5 编辑业务单据的边界

销售和采购的通用更新接口只更新主单字段及金额计算结果，不会重新执行创建时的批次扣减/入库、成本分摊、应收或应付同步：

- 修改销售数量、商品、采购来源或价格，不会反向恢复旧批次并按新数据重新出库。
- 修改采购数量、商品或价格，不会更新采购明细、库存批次、库存汇总和应付。
- 销售金额重算会把主单已收金额重置为 0，但不会同步修改既有应收和资金流水。
- 采购金额重算会把主单已付金额重置为 0，但不会同步修改既有应付和资金流水。
- 维修更新可以触发完成处理，但不会重建已经创建的维修明细，而且整个更新和完成副作用没有统一外层事务。

因此，已经产生库存或财务副作用的销售、采购、维修单不应通过通用编辑改变核心数量和金额。生产化前应限制可编辑字段，或实现带原单反冲和重新过账的专用修改流程。

## 10. 权限、演示模式和数据范围

- 所有受保护接口都需要有效 Access Token；密码版本变化后旧令牌失效。
- 模块分别使用 `sales.manage`、`purchase.manage`、`inventory.manage`、`repair.manage`、`project.manage`、`finance.manage` 等权限。
- 删除业务单据除模块权限外，还需要 `document_delete`。
- 审计和删除记录需要 `system.audit.view`。
- 演示模式只阻止修改密码以及用户、角色、权限、菜单的写操作；普通销售、采购、库存相关业务写操作并未被演示模式统一禁止。
- 角色数据范围会被解析并放入请求上下文，但当前业务仓储查询尚未使用该上下文过滤数据；现阶段实际隔离主要依赖 `tenant_id`。

## 11. 恢复测试数据

“恢复测试数据”在单个事务中执行，会清空当前租户的业务、库存、财务、往来、对账、删除记录、图片和审计日志，并重置相关 SQLite 自增序列，然后重新写入：

- 4 个演示客户
- 4 个演示供应商
- 5 个演示商品
- 4 个资金账户及示例期初余额

用户、角色、权限和菜单不会被删除，但用户最后登录时间和 IP 会被清空。该操作具有破坏性，只应在演示或测试环境执行。

## 12. 事务与一致性边界

以下流程当前有完整外层事务：

- 创建销售、采购、维修及其创建副作用
- 生成、确认和结算客户对账单
- 删除销售、采购和维修单
- 恢复测试数据

以下流程当前没有包裹完整外层事务：

- 更新维修单后触发完成处理
- 单独登记应收收款
- 单独登记应付付款

这些流程中若后续数据库操作失败，前面的部分更新可能已经成功。生产化前建议补充事务封装、幂等键和失败补偿测试。

## 13. 主要状态速查

| 对象 | 当前实际使用或识别的状态 |
| --- | --- |
| 采购批次 | `未销售`、`销售中`、`已销售完成` |
| 库存汇总 | `正常`、`预警` |
| 应收 | `unpaid`、`partial`、`overdue`、`paid`、删除后的 `已冲销` |
| 应付 | `unpaid`、`partial`、`paid`、删除后的 `已冲销` |
| 对账单 | `unconfirmed`、`confirmed`、`settled` |
| 对账明细 | `unpaid`、`partial`、`paid`、销售删除后的 `已冲销` |
| 删除处理 | `PROCESSING`、`SUCCESS` |
| 维修完成触发值 | `completed`、`已完成`、`结算完成`、`维修完成` |

状态值目前中英文并存。扩展业务时应优先统一后端枚举、迁移旧数据，并让前端只负责显示映射。
